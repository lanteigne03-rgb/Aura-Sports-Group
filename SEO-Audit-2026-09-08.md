# SEO Audit — Aura Sports Group (aurasmg.com)
**Date:** September 8, 2026
**Scope:** New static site in the `Aura-Sports-Group` GitHub repo (13 pages) + the currently live domain

## The headline issue: two different sites

`aurasmg.com` and `www.aurasmg.com` are **currently live on Wix** — title tag "AURA Sports Management Group | Aura Sports," no meta description, `meta-generator: Wix.com Website Builder`. The Wix `robots.txt` and `sitemap.xml` are still active and reference Wix-only paths (`/pro-gallery-webapp/`, etc.).

The repo, meanwhile, contains a **complete, unlaunched rebuild** — 13 static HTML pages with a `CNAME` file pointing at `aurasmg.com`, ready for GitHub Pages but not yet deployed there (or DNS hasn't cut over). Good news for the migration: the live Wix sitemap only lists **one indexed URL** (the homepage), so there's minimal existing search equity to protect — this is about as clean a migration as it gets. Still, a few things need to happen at cutover, listed under Critical below.

Everything after this section audits the **new repo site**, since that's what will actually go live.

## Critical (fix before or at launch)

**No `robots.txt` or `sitemap.xml` in the new repo.** Neither file exists anywhere in the site source. Once this replaces the Wix site, there will be nothing telling search engines what to crawl or listing the 13 pages to index. Add both at the root before cutover.

**Homepage has no H1 and no headline text at all.** `index.html`'s hero is just the logo image (`alt="Aura Sports Group"`) — there's a `.hero-inner h1` CSS rule and even keyframe animations for a `.hero-line` headline, but no actual heading element or headline copy in the markup. The single highest-value page on the site currently has zero keyword-carrying text in its hero.

**`representation.html` also has no H1.** Its content is four `<h3>` cards (NFL / College / Recruits / Coaches) and nothing else — 13 words of body text total.

**No structured data anywhere.** None of the 13 pages carry JSON-LD. For a sports agency, an `Organization` or `SportsOrganization` schema on the homepage (with `sameAs` links to your Instagram/X/LinkedIn, which are already in the footer) is low effort and gives Google and AI answer engines a clean entity to key off of.

**No canonical tags on any page.** Trivial to add (`<link rel="canonical" href="...">`), and cheap insurance against duplicate-content issues (e.g., `aurasmg.com` vs `www.aurasmg.com` — the Wix sitemap uses `www`, worth deciding which is canonical before launch and 301'ing the other).

## High priority

**Navigation and footer are 100% JavaScript-injected, with no static fallback.** Every page loads `<div id="nav-placeholder">` / `<div id="footer-placeholder">` and `js/site.js` writes the actual `<a>` tags in at runtime. View-source on any page shows zero navigational links. Modern Googlebot generally renders JS, but this means: no-JS users and simpler crawlers get a page with no navigation at all, internal link equity depends entirely on successful JS execution, and the render step adds latency to when links are discoverable. A static `<nav>` in the HTML (even if JS then enhances it) would be safer.

**Several pages are extremely thin on content**, which matters more once there's no nav text for a crawler to fall back on:
| Page | Approx. word count |
|---|---|
| `representation.html` | ~13 |
| `brand-inquiries.html` | ~26 |
| `contact.html` | ~33 |
| `our-team.html` | ~45 |
| `index.html` | ~55 |

Your own README already flags `brand-inquiries.html` as "currently a placeholder shell" and `our-team.html` as needing real profiles — worth doing before launch, not just after, since thin/placeholder pages are exactly what tends to sit flat in search.

**Unoptimized media weight will hurt Core Web Vitals (LCP) and mobile data usage:**
- `Hero-Vid-Loop.mp4` — **36 MB**, autoplaying on the homepage
- `high-school-hero.jpg` — 2.1 MB, `nfl-hero.jpg` — 1.8 MB, `coach-hero.jpg` — 1.7 MB, `college-hero.jpg` — 1.5 MB (all full-bleed hero images, each on its own page)

These should be compressed and served as WebP/AVIF with a JPG fallback; hero images at this size are typically 150–400 KB when optimized. The video in particular is a likely LCP/load-time problem on mobile connections.

**Hero images have empty `alt=""` despite being meaningful content, not decoration:** `coach-hero.jpg`, `college-hero.jpg`, `nfl-hero.jpg`, `high-school-hero.jpg` all use `alt=""`. (The two logo "glitch" clones on the homepage correctly use `alt="" aria-hidden="true"` — that's fine, they're decorative duplicates of a labeled logo. The hero photos are different — they're the main visual on their respective pages and should describe what's shown, e.g. `alt="Aura Sports Group coach on the sideline"`.)

## Already in good shape

- **Titles**: unique per page, descriptive, well within length limits (29–51 characters — you actually have room to use more of the ~60-char budget on shorter ones like `contact.html` and `our-team.html`).
- **Meta descriptions**: unique on every page, none over 160 characters. `terms.html` (64) and `brand-inquiries.html` (63) are on the short side and could say more.
- **Open Graph tags**: `og:title`, `og:description`, `og:image`, `og:url` present on all 13 pages — good for social sharing.
- **Favicon package**: full set (ico, 16/32px png, apple-touch-icon) — complete.
- **`lang="en"`** set correctly on every page.
- **Viewport meta** present on every page — mobile-responsive baseline is there.
- **11 of 13 pages have a single, correctly-placed H1** (only the homepage and `representation.html` are missing one).

## Suggested order of operations

1. Finish the README's own "before launch" checklist (placeholder copy/photos on Recruits, Coaches, Our Team, Brand Inquiries) — this is both a content and an SEO fix.
2. Add `robots.txt` + `sitemap.xml`, canonical tags, and an H1/headline to `index.html` and `representation.html`.
3. Add basic `Organization` JSON-LD schema to the homepage.
4. Compress hero images and the homepage video; fix the four empty hero `alt` attributes.
5. At cutover: decide `www` vs. non-`www` as canonical, set up the redirect, submit the new sitemap in Search Console, and retire the Wix sitemap/robots.txt.
6. Longer-term: consider server-rendering (or at least duplicating into static HTML) the nav/footer links rather than relying solely on client-side JS injection.
